# Permanent request deletion

Only a superadmin can use **სრულად წაშლა** in a request's details or its archive entry. The confirmation names the request and warns that offers, chat, orders and order history are permanently removed from all panels. Ordinary admins, customers and shops cannot start or perform this cascade. Demo mode does not expose the action.

Deletion removes the request (including embedded photos), every linked offer and message, the request's order and its complete nested event history, and request/offer labels archived in all five panels of all member accounts. Other requests, shop profiles, Auth accounts, member roles, categories and device tokens are preserved. Private inbox read receipts contain only source IDs/timestamps; they are harmless after the actual notification sources are removed and do not display an item by themselves.

This works with the current Firestore Standard project and does not require Cloud Functions or a billing change. Before removing data, the client creates `pf_deletions/{requestId}` with only `requestedBy`, `status`, `createdAt` and `updatedAt`. Rules restrict that lock to superadmins, require an existing request, and immediately block new offers/messages/order updates/archive markers and later recreation of the request ID. The lock holds no request content and cannot be removed through client rules.

Deletion is a bounded, resumable cascade rather than an unlimited atomic transaction. Data is removed in batches of at most 100; archive offer queries use at most five IDs to stay within rule lookup limits. User accounts and offers are paged without the normal panel 300-record cap. The request root is removed last, atomically with completion of the lock. An interrupted job stays in **დასასრულებელი წაშლა** in the superadmin panel; **წაშლის გაგრძელება** safely resumes it. During this interval participants cannot add new linked content. A completed retry is a no-op.

Superadmin archive read/delete access is restricted to request/offer markers associated with a pending deletion, while ordinary private archive ownership rules stay in place. Normal admins still cannot delete immutable history. Superadmin history deletion is permitted only as part of a locked full-request cascade. Optional Push triggers check the lock before sending queued source events.

Verification: `node tests/deletion.mjs` against the local demo emulator checks role denials, required lock, forged/missing locks, immutable lock ownership, cross-request isolation, blocked racing writes/recreation, 520 messages, 105 history events, multiple offer pages, archived copies, interrupted resume, completed retry, and live removal from an independent shop subscription. Existing rules/archive/realtime/commerce suites pass. Browser QA checks confirmation cancel/accept, permanent request/offer removal, live shop disappearance and unrelated request preservation using disposable emulator accounts only. No production request was deleted during development.
